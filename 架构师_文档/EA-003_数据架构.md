# EA-003 · 数据架构文档（Data Architecture）
**TOGAF ADM Phase C – Data** · 2026-03-21 · v1.0

---

## 1. 文档目的

本文档依据 TOGAF ADM Phase C 数据架构要求，描述萨米特核心素养平台的逻辑数据模型、物理数据模型、数据分类、数据流向及数据质量策略。

## 3. 逻辑数据模型（Logical Data Model）

### 3.1 核心素养领域模型

```
capability_domain (DE-01)
│   id, name, sort_order
│
└──< capability_dimension (DE-02)
        id, domain_id(FK), name, description, sort_order
        │
        ├──< capability_level (DE-03)
        │       id, dimension_id(FK), level[0-8], description
        │       UNIQUE KEY (dimension_id, level)
        │
        └──┤ dimension_curriculum (DE-04)
                id, dimension_id(FK UNIQUE), language, social, science
```

### 3.2 PBL 项目模型

```
pbl_project (DE-05)
    id, sort_id, pa_type, is_certified, category, subject,
    course_name, china_grade, grade_level,
    grade_6~grade_12[BOOL×7], duration,
    name_en, name_zh, url_original, url_translation, notes

pbl_project_instructions (DE-06)   ← 自引用树形结构
    id, parent_id(FK→self, NULL=一级节点),
    title(中文), en_title(英文), number

pbl_project_sample (DE-07)
    id, instruction_id(FK→DE-06), content

关系：DE-06 自引用（parent_id CASCADE）
      DE-07 → DE-06 一对一（instruction_id）
```

### 3.3 公开 PBL 项目模型

```
pbl_open_project (DE-09)
    id, pa_type, is_certified, category, subject,
    course_name, china_grade, grade_range, duration,
    grade_6~grade_12[BOOL×7],
    name_en, name_zh, url_original, url_translation,
    sort_num, notes, rubric_notes,
    --- 36个能力维度标记 (d_前缀, TINYINT 0/1) ---
    d_theme_main_idea, d_viewpoint_purpose, d_development,
    d_structure, d_word_choice,                          ← 文本分析(精读) 5维
    d_select_source, d_contextualize_source,
    d_synthesize_source,                                  ← 使用资料 3维
    d_raise_question, d_define_problem,
    d_predict_hypothesis, d_design_procedure,             ← 探究 4维
    d_identify_patterns, d_compare_contrast,
    d_modeling, d_interpret_data, d_build_connections,
    d_evaluate_solutions, d_evaluate_arguments,
    d_design_solution, d_build_evidence,                  ← 分析与综合 (部分)
    d_argumentation, d_informational_essay,
    d_narrative, d_counter_argument, d_select_evidence,
    d_interpret_evidence, d_integrate_evidence,
    d_organization, d_intro_conclusion,                   ← 创作/写作 9维
    d_discussion, d_style_listening,                      ← 听/说 2维
    d_oral_expression, d_multimedia,
    d_precision,                                          ← 产出/演讲 3维
    local_file, download_status
```

### 3.4 参考文献模型

```
pbl_references (DE-08)
    id, seq, type, author, year,
    title(英文原标题), title_zh(中文标题),
    source, link, notes,
    link_type[url|pdf|text|null],
    local_file, download_status
```

### 3.5 PARB 外部资源模型

```
pbl_project_summit_resources (DE-10)
│   id, title, url, task_type, subject, course,
│   grade_level, grade_level_span, duration,
│   student_collaboration, source, rating, description
│
├──< pbl_project_summit_files (DE-11)
│       id, resource_id(FK), file_type[download|rubric],
│       title, url, sort_order,
│       is_downloaded, local_path
│
└──>< pbl_project_summit_standards (DE-12)  ← 多对多
         id, code, url
         via: pbl_project_summit_resource_standards (DE-13)
              resource_id, standard_id [PK联合]
```

## 4. 数据分类（Data Classification）

| 分类 | 数据类型 | 示例 | 敏感级别 |
|------|----------|------|----------|
| 框架数据 | 能力域/维度/水平描述 | 7域36维324水平 | 低（公开内容） |
| 项目数据 | PBL项目元数据、指导结构 | 36个认证项目 | 低（公开内容） |
| 文献数据 | 参考书目、链接 | 60条学术文献 | 低（公开引用） |
| 外部资源 | PARB下载文件 | 11个.docx/.pdf | 中（版权内容） |
| 系统数据 | 数据库连接配置 | .env 文件 | 高（不可外泄） |

## 5. 数据质量规则（Data Quality Rules）

| 规则 ID | 规则描述 | 检查方式 |
|---------|----------|----------|
| DQ-01 | capability_level 每个维度必须有 9 条记录（0~8 级） | `UNIQUE KEY (dimension_id, level)` |
| DQ-02 | dimension_curriculum 每个维度有且只有一条课标记录 | `UNIQUE KEY (dimension_id)` |
| DQ-03 | pbl_project_instructions 自引用 parent_id 须指向已存在节点 | `FK CASCADE` |
| DQ-04 | pbl_open_project 中 grade_6~grade_12 字段由原始 XLSX 单元格颜色决定，不可手动推断 | 导入脚本颜色检测 |
| DQ-05 | pbl_references.link_type 须为 [url/pdf/text/null] 之一 | 导入脚本分类逻辑 |
| DQ-06 | 所有中文标题 title_zh 来源于 Google Translate API，需人工抽查准确性 | 定期人工复核 |

## 7. 数据生命周期管理（Data Lifecycle）

| 阶段 | 操作 | 负责方 | 工具 |
|------|------|--------|------|
| 采集 | 从 XLSX/网页提取原始数据 | 管理员 | Excel、Playwright MCP |
| 导入 | 运行 import_*.js 脚本入库 | 管理员 | Node.js + mysql2 |
| 翻译 | 中文标题机器翻译 | 自动化 | Google Translate API |
| 存储 | MySQL 持久化 | 系统 | MySQL 数据库 |
| 检索 | API 查询（支持筛选/关键词） | 系统 | Express + SQL |
| 展示 | Vue 组件渲染 | 系统 | Vue 3 + Axios |
| 备份 | SQL 脚本导出 | 管理员 | export_sql.js |
| 归档 | sql/ 目录 .sql 文件 | 管理员 | Git 版本控制 |

---

## 8. 数据备份策略

- **备份工具**：`sql/export_sql.js`（SHOW CREATE TABLE + SELECT * 拼接标准 SQL）
- **备份文件**：`sql/` 目录下各表 `.sql` 文件，可直接重建表结构与数据
- **版本控制**：备份文件纳入 Git 仓库管理
- **恢复流程**：执行对应 `.sql` 文件即可重建所有数据表
